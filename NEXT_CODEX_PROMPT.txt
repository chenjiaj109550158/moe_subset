## Oracle subset 定義

對每個 MoE layer 分別選 subset。

Horizons：

`H = [1, 2, 4, 8, 16]`

Budgets 至少包含：

Qwen：
- native top-k = 8
- `B = [8, 16, 32, 64, 128]`

GPT-OSS：
- native top-k = 4
- `B = [4, 8, 16, 24, 32]`

其中 all-expert budget 只作 reference，不可算節省。

Selection methods 至少包含：

1. future selected-routing-mass oracle；
2. future binary-count oracle；
3. previous-route baseline；
4. static-frequency baseline。

若 full-router-mass 能以 native semantics 正確取得，也加入；不可用不相容的 proxy 冒充。

## 執行 policies

至少比較：

1. `natural`
   - 原始 native routing reference。

2. `lossless_oracle_residency`
   - 預載 oracle subset。
   - natural route 選中 subset 外 expert 時 demand fallback/load。
   - 必須保持 native IDs/weights 和輸出。
   - 測 fallback frequency、load bytes、subset churn、exposed stalls。
   - 不可把它描述成 accuracy improvement。

3. `hard_oracle_commitment`
   - window 內只能執行 subset experts。
   - 對 subset 外 router logits 做明確 mask，再在 subset 內依 native規則 top-k/renormalize。
   - 必須實際 closed-loop forward/generate，不能從 vanilla identity-materialize。
   - 記錄第一個 token divergence、route divergence、NLL/perplexity 與 task accuracy。

4. 至少一個 non-oracle hard baseline：
   - previous-route 或 static-frequency commitment。

清楚定義 shared experts、routed experts、layer-scoped IDs、routing scaling、normalization、MXFP4 限制及 cache rewind/replay semantics。

## 避免不必要地重跑 vanilla

優先重用 v17 保存的 prompts、targets、generated token IDs 與 evaluator。

若需要 natural route traces：

- 對保存的 vanilla prompt/token trajectory 做 teacher-forced replay，收集每 token、每 layer 的 native IDs、weights、router scores；
- 驗證 replay logits/routes 與原始 generation parity；
- 不要重新做整套昂貴 vanilla autoregressive benchmark，除非有證據顯示 replay 不可靠。

Lossless policy 可先以 route replay/simulation 取得完整 fallback 與 transfer metrics，再以跨 task smoke 做 real-forward identity validation。

Hard commitment 必須真正 generation，使用與 v17 完全相同的 prompt rendering、decoding、token caps、evaluator 和 dataset revisions。

## 分階段執行

### A. Trace與open-loop grid

先跑完整或預先固定的代表樣本 route replay，產生所有 `(H,B,method)` 的：

- route hit rate；
- selected/full routing-mass coverage；
- expert-union size；
- subset churn；
- estimated H2D bytes/token；
- mean、median、P05、P95、worst；
- layer/task/context/router-margin 分層結果。

保存 concrete worst cases。

### B. Closed-loop smoke

以預先固定、不能看 accuracy 後更換的 sample IDs，驗證：

- hard commitment 確實改變 executed route；
- lossless fallback exact-token identity；
- evaluator、resume、sharding、CUDA placement；
- GPT AIME 32,768-token 上限不被重新截成 4,096。

### C. Full benchmark accuracy

只可依預先聲明的 open-loop coverage/transfer 條件選擇少量 Pareto operating points，不可根據 smoke accuracy 挑點。

對入選 operating points 跑完整六個 dataset hard closed-loop accuracy。長實驗必須：

- resumable；
- sample/shard 原子落盤；
- 每 GPU 最多一個 32k worker；
- 記錄 PID/PPID、physical GPU、config fingerprint；
- 程序完成後自動 aggregate、validate、report。

## Predeclared gate

候選 operating point 必須同時滿足：

- expert residency 明顯低於 all-expert；
- mean route hit ≥ 0.90；
- selected routing-mass coverage ≥ 0.95；
- P05 與 worst hit ≥ 0.80；
- estimated transfer reduction ≥ 30%；
- 相對 previous/static baseline 有實質改善；
- lossless fallback frequency ≤ 0.10；
- hard commitment benchmark accuracy 相對本地 v17 vanilla 的下降不超過預先計算的 paired uncertainty gate；
- 不可用跨 task macro average 掩蓋單一 dataset failure。

HumanEval/MBPP+ 使用相同 execution sandbox；GSM8K/AIME/StrategyQA 使用相同 answer parser。AIME 的離散差異必須同時列出題數，不只百分比。

最終對每個 model、task、`(H,B)` 分別判定：

- GO
- NARROW
- STOP/PIVOT

只有 GO 或明確限定範圍的 NARROW 才授權後續 learned subset selector。若 perfect oracle hard commitment 都失敗，停止訓練 predictor。
